01 · Language model

MangARTI

A fine-tuned Llama 3 8B that translates between formal Bahasa Indonesia and Manado Malay, also called Manadonese, in both directions. It was trained on a dataset written with native speakers, on a single laptop GPU.

View code Opens MangARTI on GitHub in a new tab View model Opens MangARTI on Hugging Face in a new tab

At a glance

Task
Sentence translation, formal Indonesian to Manado Malay and back
Base model
Llama-3-8b-Instruct-bnb-4bit, Llama 3 8B Instruct quantised to 4-bit
Method
QLoRA, with Unsloth and PEFT
Dataset
About 7,000 Alpaca-format examples in JSONL, published on Hugging Face (opens in a new tab)
Hardware
One consumer gaming laptop with an NVIDIA RTX 5050
Status

The catalyst

MangARTI started as a final school project, and it started small. The first version was a Naive Bayes classifier that sorted text into two classes: Manadonese or formal Bahasa Indonesia. For a language with almost no tooling it was a sensible first model, cheap to train and easy to inspect.

A peer challenged it with a simple question: what would anyone do with the answer? Speakers of Manadonese already know which language they are reading, and a label does nothing for someone who understands only one side of the pair. The question was harder to dismiss than any accuracy figure, so the project changed shape, from labelling the dialect to translating it with a fine-tuned large language model.

Why word-for-word translation was never an option

The obvious shortcut for a dialect this close to formal Indonesian is a lookup table: map each Manadonese word to its formal equivalent and substitute. Manado Malay defeats that approach twice.

First, it is a near-zero resource language. There is no large parallel corpus to learn from, and very little Manadonese in the text that general-purpose models are trained on. Second, it has no standardised orthography. People write it the way they speak it, so a single word arrives in several spellings:

A dictionary keyed on spelling fails on the first variant it has not seen. A language model can learn from context that these forms carry the same meaning, which is why the project needed one.

A human-in-the-loop data pipeline

With no corpus to download, the dataset had to be produced. The pipeline splits the work by what each participant does best: a general model drafts at volume, and people supply the judgement that cannot be automated.

  1. Draft the source sentences

    Gemini 3.2 Pro generated everyday sentences in formal Indonesian, giving the dataset breadth without asking volunteers to invent material.

  2. Translate with native speakers

    I coordinated a group of native-speaker volunteers who translated the sentences into Manadonese by hand, so the target side reflects how the dialect is actually used.

  3. Write every pair in both directions

    Each sentence pair becomes two training examples, formal to Manadonese and Manadonese to formal, so one model serves both directions.

  4. Format as Alpaca JSONL

    Every example carries an instruction, an input and an output, stored one per line in JSONL. The same Alpaca template is used in training and at inference, so the model is always asked in the format it learned.

The finished dataset holds about 7,000 examples and is published openly on Hugging Face as Bahasa-Manado-Alpaca-Translations (opens in a new tab).

Training on one laptop GPU

All training ran locally on a consumer gaming laptop with an NVIDIA RTX 5050. Its VRAM ruled out conventional fine-tuning of an 8-billion-parameter model, so the hardware chose the method before any experiment did.

The base model is Llama 3 8B Instruct, loaded as a 4-bit bitsandbytes quantisation (Llama-3-8b-Instruct-bnb-4bit). QLoRA leaves those quantised weights frozen and trains small low-rank adapters on top of them, which brings the memory needed for training within reach of a laptop card. Training runs through Unsloth and TRL's supervised fine-tuning trainer, with gradient checkpointing and an 8-bit optimiser to stretch the memory budget further. The published training script uses this configuration:

Adapter
LoRA rank 16, alpha 16, no dropout
Target modules
Every attention and MLP projection: q, k, v, o, gate, up, down
Sequence length
512 tokens
Batch
Batch size 1 per device, 8 gradient accumulation steps (effective batch 8)
Optimiser
8-bit AdamW, learning rate 1e-4, cosine schedule, 50 warm-up steps
Epochs
2

Fixing hallucinations in the data, not the hyperparameters

Early versions hallucinated severely: translations that read fluently but did not say what the source said.

The tempting response is to tune: lower the learning rate, train for longer, change the adapter rank. That was not where the problem was. The fix was a rigorous, manual revision of the dataset, example by example, until the data was clean enough to learn from.

On a dataset of about 7,000 examples, every bad example is a meaningful share of what the model learns, and no hyperparameter compensates for it.

Known limits

MangARTI is trained on single sentences, and it is documented that way: paragraphs and long documents fall outside its training data and degrade the output. Casual Manadonese typed in chat, with its shifting slang, abbreviations and non-standard spellings, remains the hardest input, so the model card recommends entering one sentence at a time in relatively standard spelling. It is not meant for medical, legal or other high-stakes translation, and translations it produces should be presented as AI-generated.

Next: MangARTI mini

An 8B model, even quantised, still asks for a capable GPU every time it runs. MangARTI mini replaces it with highly efficient models of around one billion parameters, and I am experimenting with Qwen and Llama models at that size.

The goal is accessibility. A translator for a regional dialect is most useful when it runs on the hardware its speakers already own, not only on a gaming laptop.

02 · Web application

IterMath

A practice tool for core math skills: seven modules, from addition to permutations, each generating new problems and showing the solution after every wrong answer.

Open IterMath (opens in a new tab)
Modules
Addition, subtraction, multiplication, division, mixed arithmetic, combinations (nCr), permutations (nPr)
Problems
Generated in the browser, typeset as LaTeX with MathJax
Stack
Static HTML and JavaScript, no backend, no accounts
Address
itermath.jomontolalu.com

The problem

Students often drill the same concept without making progress. Repetition builds fluency only when each attempt ends in clear feedback, and a worksheet gives none until someone marks it.

How it works

Each module generates its problems procedurally, and the generators are built so the arithmetic always comes out clean. A division problem is created from its answer, so the quotient is always a whole number. Subtraction always takes the smaller number from the larger, so no negative result reaches a beginner. Mixed arithmetic draws from six expression templates that guarantee integer answers.

A correct answer moves straight on to the next problem. A wrong one stops and shows the method: for combinations and permutations, the full factorial derivation down to the number; for mixed arithmetic, the correct result with a reminder of the order of operations.

Why it is built this way

There are no accounts and no server. Every module is a static page, so practice starts as soon as it loads, on any device with a browser. The loop of attempt, then explanation, is the whole product, and nothing else stands between a student and the next problem.

03 · Web application

BSQShuttle

An unofficial timetable for the Binus Square shuttle that reads the device clock to show the last departure, the next one, and the full schedule for the Kemanggisan, Alam Sutera and JWC/FX routes.

Open BSQShuttle (opens in a new tab)
Routes
Kemanggisan (BSQ, Kijang, Syahdan, Anggrek), Alam Sutera and JWC/FX
Timetable
33 daily departures across three routes
Stack
One static HTML page with vanilla JavaScript, no backend
Status
Independent student project, not affiliated with Bina Nusantara

The problem

Students living at Binus Square take a shuttle to campus, and a missed bus is costly: the Alam Sutera route runs only three times a day. Checking the schedule should take seconds and answer one question: when the next bus leaves.

How it works

Each route is stored as structured data: the departure time, the intermediate stops, the arrival and the unit running it. The page reads the device clock, marks the last departure and the next one, and highlights the next row in the timetable, refreshing every minute.

The Kemanggisan route mixes three kinds of run: regular buses that stop at Kijang and Syahdan, bypass buses that go straight to Anggrek, and departures served by two units at once. Filters show one kind at a time. Each route also carries the operator's notes, such as a full bus leaving before its scheduled time, or schedules changing during online classes.

Why there is no backend

A timetable of 33 departures does not need a database or an API. Keeping it as data inside one static page means the page loads quickly on a phone and has nothing to keep running.
